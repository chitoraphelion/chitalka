#### Ревью Markdown/KaTeX (64a3ce2) и личные заметки

Независимое ревью коммита Codex `64a3ce2` (родитель `0db24fa`) по коду, а не по описанию,
и доработки по требованиям: чистое открытие любых PDF/Markdown, личные заметки `N`.
Каждая найденная проблема сначала воспроизводилась отдельной пробой.

#### Найденные проблемы и решения

- Незакрытый `$$` в Markdown поглощал весь текст до следующего `$$`, включая заголовки
  (проба: из трёх разделов оставался один, заголовок исчезал из оглавления).
  Блочная формула больше не переходит через пустую строку — как в LaTeX.
- Относительная ссылка выше корня (`../../../etc/x.md`) молча превращалась в `etc/x.md`
  внутри проекта, то есть вела в другой файл (поведение `URL()` при нормализации).
  Путь теперь нормализуется вручную; ссылки и картинки за корнем отключаются с подсказкой.
- Открытие документа писало `kommentarii/HOW_TO_USE_CHITALKA.md`; даже `chitalka list`,
  `where` и чтение пустого хранилища создавали `kommentarii/` и lock-файл
  (проба подтвердила). Чтение больше ничего не создаёт и не берёт блокировку
  (запись атомарная); папка, файл и памятка появляются при первом сохранённом замечании
  агенту или по явному `chitalka init`. `reply/done/reopen` при отсутствующем хранилище
  завершаются ошибкой без побочных эффектов; правка/удаление несуществующего — 404 без создания.
- Лог `--watch` лежал в `kommentarii/latexmk.log` и создавал папку при старте сборки.
  Теперь `~/.local/state/chitalka/latexmk/<проект>-<хеш>.log`; путь печатает `chitalka where`.
- Ошибка записи (папка только для чтения) роняла обработчик запроса: соединение рвалось,
  интерфейс показывал «Failed to fetch». Теперь сервер отвечает понятным сообщением,
  редактор с текстом остаётся открытым.
- Ключи `localStorage` различались только документом: на одном порту черновики и
  позиция одного проекта показывались в другом. Добавлен идентификатор проекта;
  настройки вида (тема, панели) общие; старые ключи читаются как запасные и переносятся.
- Подсветки в Markdown не пересчитывались при изменении ширины окна (текст переносится,
  прямоугольники остаются прежними) — давало горизонтальную прокрутку. Перерисовка
  при ресайзе и обрезка слоёв подсветки по странице.
- Произвольный PDF вне текущей папки получал корнем текущую папку: комментарии
  оказались бы, например, в `~/kommentarii`. Корень — папка PDF (или проект над `build/`
  при наличии `main.tex`). Для Markdown так уже было.
- Тест Codex закреплял создание памятки при открытии — переписан под ленивое создание.

#### Личные заметки (N)

- Отдельный sidecar `<полное-имя-документа>.notes.json` рядом с настоящим файлом
  документа (symlink на документ разрешается), без каталогов; создаётся при первом
  сохранении. Формат `{"format": "chitalka-personal-notes", "version": 1, "notes": [...]}`.
- Отдельный API `/api/notes`; заметки не попадают в `/api/comments`, `chitalka list/show/reply`,
  экспорт замечаний, памятку и очередь агента. В памятке только правило: `*.notes.json` —
  не поручения. Это исключение из доставки, а не защита файла от агента с доступом к диску.
- Запись: блокировка `flock` в `~/.local/state/chitalka/locks/` (рядом с документом lock-файла
  нет), временный файл в той же папке и `os.replace`, `fsync`. Symlink вместо sidecar и
  повреждённый JSON не читаются как пустые и не перезаписываются (ответ 409 с причиной).
  Поля проверяются по типу и длине. Папка только для чтения: чтение работает, сохранение
  даёт понятную ошибку, текст остаётся в редакторе и копируется в черновик браузера.
- Интерфейс: вкладки «Агенту / Мои заметки», отдельный редактор и карточки (фиолетовая
  пунктирная рамка, «Моя заметка»), своя подсветка в тексте, кнопка «Заметка N» на панели
  выделения, `N` по коду клавиши (любая раскладка), заметка без выделения — к текущему
  месту, правка, удаление с отменой, `J`/`K` по заметкам на их вкладке. `C` не изменился.

#### Остаточные ограничения

- Внешние `http(s)`-изображения в Markdown по-прежнему загружаются из сети.
- `$$…$$` посреди абзаца отрисовывается блоком внутри `<p>` (видно правильно, HTML не строгий).
- Поиск в Markdown ищет по тексту и TeX-исходнику формул (`$…$`), не по отрисованным символам.
- Заметки привязаны по цитате и контексту; после правки текста помечаются «текст изменён»
  и не перепривязываются автоматически.
- Заметка к `build/main.pdf` лежит в `build/`: `rm -rf build` удалит и её.
- Блокировки заметок рассчитаны на одного пользователя одной машины; сетевые ФС не проверялись.
- Старые черновики браузера без идентификатора проекта один раз перенесутся в первый
  открытый проект.
- Открытие nvim во вкладке kitty (`kitty @ launch`) автотестами не покрыто.
