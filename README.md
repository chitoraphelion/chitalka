**chitalka** — читалка PDF, Markdown и Jupyter-ноутбуков с LaTeX-формулами для работы с ИИ-агентом.
Автор выделяет фрагмент и пишет, что исправить; агент видит комментарий с местом
в `.tex`, `.md` или `.ipynb`, правит исходник и отвечает в той же карточке.

#### Установка

```sh
uv tool install -e ~/code/python/chitalka
```

Python 3.10+, без Python-зависимостей. PDF.js, markdown-it, KaTeX и шрифты входят
в пакет; для отрисовки документов подключение к интернету не требуется.

#### Запуск

Из корня проекта: `main.tex` в `.`, PDF — `./main.pdf` или `./build/main.pdf`.

```sh
chitalka                  # открыть ./main.pdf (или ./build/main.pdf)
chitalka build/paper.pdf  # другой PDF
chitalka notes.md         # Markdown с формулами; изменения видны автоматически
chitalka analysis.ipynb   # Jupyter-ноутбук с сохранёнными выводами
chitalka ~/Downloads/x.pdf  # любой PDF для чтения; корень — его папка
chitalka --watch          # заодно latexmk -pvc -synctex=1 и автообновление
chitalka --help
```

Открытие ничего не создаёт рядом с документом: ни папок, ни lock-файлов, ни памятки.
Замечания агенту хранятся в `./kommentarii/kommentarii.json`, рядом — `HOW_TO_USE_CHITALKA.md`,
памятка для агентов; папка, файл и памятка появляются при первом сохранённом замечании
(или по явному `chitalka init`). `chitalka list` и `where` только читают.
Каждый проект занимает свой порт; повторный запуск в той же папке
использует работающую читалку. Разные документы открываются в отдельных вкладках
с собственными комментариями; команды агентов показывают замечания всего проекта.

#### Markdown и формулы

```sh
chitalka README.md
chitalka notes/draft.md --root .     # комментарии хранятся в корне проекта
chitalka ~/paper/notes.md            # корень по умолчанию — папка этого файла
chitalka examples/optimization.md    # пример из этого репозитория
```

Поддерживаются `.md` и `.markdown`: заголовки с оглавлением, списки и задачи,
таблицы, цитаты, ссылки, изображения, блоки кода, выделение и зачёркивание.
Локальные изображения и ссылки на другие Markdown/PDF разрешаются относительно
документа внутри корня проекта; ссылки за его пределы отключаются (а не ведут
в другой файл). Незакрытый `$$` не «съедает» текст дальше пустой строки. HTML показывается как текст.

Математика отрисовывается KaTeX:

- В строке: `$x_k - \eta\nabla f(x_k)$` или `\(x^2\)`.
- Отдельно: `$$ ... $$` или `\[ ... \]`, в том числе многострочные `aligned`,
  матрицы, дроби и суммы. В коде формулы не обрабатываются; `\$` — обычный доллар.
- Это поддерживаемый KaTeX математический синтаксис, а не компиляция полного LaTeX-документа.
  Ошибка в формуле остаётся видна в документе и не мешает читать остальное.

Markdown раскладывается на листы A4, как PDF: лист 210×297 с полями, заголовок не
остаётся последним на листе, длинные списки переносятся по пунктам, блок выше листа
(большая таблица или код) получает свой лист. Разбиение не зависит от масштаба, поэтому
номера страниц стабильны. Остаются поиск, темы, масштаб, выделение, замечания (`C`) и заметки (`N`). Замечание содержит `document` и `source.how = "markdown"`:
`source.line`/`lineEnd` указывают **блок исходника**, например абзац или формулу,
а `quote` сохраняет текст и TeX выделенной формулы. Кнопка файла открывает `.md`
в редакторе. После правок цитата ищется заново, отсутствующая помечается изменённой.

Автообновление работает без `--watch` и без latexmk. Пока выделяется текст или
пишется комментарий, обновление откладывается. Если файл уже изменён, сохранение
нового замечания со старой привязкой отклоняется: сохраните текст в черновик,
обновите документ и выделите фрагмент заново.

В sovet можно использовать `sovet reader notes.md` или
`sovet up --reader --document notes.md`. Замечания идут в тот же поток задач писателя.

#### Jupyter-ноутбуки

```sh
chitalka analysis.ipynb
chitalka examples/notebook.ipynb     # пример: формулы, stdout/stderr, ошибка, картинки
```

Ноутбук показывается статично, как сохранён после исполнения: ничего не запускается,
ядро не нужно. Markdown-ячейки с формулами — как обычный Markdown; код — блоком с подписью
`In [n]`; сохранённые выводы — текстом (stdout, `text/plain`), stderr и ошибки — красноватым
блоком без ANSI-цветов; картинки (`png`, `jpeg`, `gif`, `webp`, `svg`) и вложения `attachment:`
встраиваются из самого файла. `text/markdown` и `text/latex` отрисовываются. Очень длинный
вывод обрезается после 5000 строк. Поддерживаются nbformat 4 и 3.

HTML показывается, как в Jupyter: таблицы pandas (и цвета Styler), оформление курсов в
markdown-ячейках — блоки с рамками и градиентами, `<font color>`, `<details>` с подсказками
(раскрываются по клику), ссылки, картинки, формулы внутри HTML; `<h1>`–`<h6>` попадают
в оглавление. HTML пересобирается по белому списку: скрипты не исполняются, `<style>`,
формы, кнопки, `svg`, обработчики событий, `id`/`class` и `url()` в стилях выбрасываются;
незакрытые теги закрываются на границе ячейки. Схема модели sklearn заменяется её `repr`,
виджеты (`tqdm`, ipywidgets) — сохранённым текстом с пометкой, что состояние в файле не
сохранено. В `.md` HTML по-прежнему показывается как текст. Высокие HTML-блоки делятся
между листами по вложенным блокам.

Дальше всё как у Markdown: листы A4, оглавление по заголовкам, поиск, `C`, `N`, автообновление
при сохранении ноутбука. Замечание содержит `source.how = "notebook"`, номер ячейки
`source.cell` (`cellEnd`, если выделение задевает несколько) и `source.line` — строку
в `.ipynb`, где начинается выделенное в коде или тексте ячейки; для вывода — последнюю строку
её кода. Кнопка файла открывает `.ipynb` в nvim на этой строке.

#### Личные заметки (N)

`N` — заметка для себя, `C` — замечание агенту. Заметка привязывается к выделению
(цитата и место) или, без выделения, к текущей странице/разделу. Хранится в одном файле
рядом с документом — `article.pdf.notes.json`, `draft.md.notes.json`, — который появляется
при первой сохранённой заметке. Заметки живут на вкладке «Мои заметки» боковой панели,
подсвечиваются в тексте фиолетовым пунктиром, их можно изменить и удалить (с отменой).

Заметки не попадают в `chitalka list/show/reply`, API замечаний, экспорт и памятку
агента и не превращаются в поручения автоматически. Это исключение из доставки агенту,
а не защита файла: агент с доступом ко всем файлам может его прочитать.
У каждого документа проекта свой файл заметок. Если папка только для чтения, документ
открывается и читается, а при сохранении появляется понятная ошибка; текст остаётся
в редакторе и копируется в черновик браузера. Ссылки-symlink вместо файла заметок
и повреждённый JSON не перезаписываются. Блокировка — в `~/.local/state/chitalka/locks/`.

#### Дерево файлов (Пробел e)

`Пробел`, затем `e` — дерево файлов проекта в духе netrw (`<leader>e` → `:Explore` в nvim):
баннер, `../` и `./`, папки сверху, относительные номера строк, строка состояния
и командная строка как в nvim. Открывается в папке текущего документа, курсор на нём.

- `j`/`k` (со счётчиком: `5j`), `gg`/`G`/`12G`, `Ctrl-d`/`Ctrl-u`, `Ctrl-f`/`Ctrl-b`, `H`/`M`/`L`, `zz`/`zt`/`zb`.
- `Enter`: папка — войти; PDF, Markdown или ноутбук — открыть в читалке; другой файл
  (`.tex`, `.py`…) — в nvim. `t` — документ в новой вкладке, `-` — папка выше
  (курсор встаёт на папку, из которой вышли), клик мышью — то же, что `Enter`.
- `/` и `?` с подсветкой по мере ввода, `n`/`N`, `:noh`; `s` — сортировка (имя, время, размер),
  `r` — обратный порядок, `gh` — скрытые файлы, `I` — баннер, `Ctrl-l` — перечитать.
- `:q` (а также `:q!`, `:wq`, `ZZ`) — выход; `:e путь` и `:tabe путь` с Tab-дополнением,
  `:12` — строка 12, `F1` или `:help` — все клавиши. `Esc`, как в netrw, дерево не закрывает.

Клавиши работают и в русской раскладке. Дерево только читает и не выходит за корень проекта.
Пробел сам по себе по-прежнему листает документ.

#### Команды для агентов

```sh
chitalka list                     # открытые, ждущие ответа (--all, --done, --json)
chitalka show ID
chitalka reply ID "текст" [--done]
chitalka done ID [ID ...] [-m "текст"]
chitalka reopen ID
chitalka init | where
```

#### Запущенные читалки и остановка

```sh
chitalka sessions                  # или chitalka ps; из любой папки
chitalka sessions --json
chitalka sessions --root ~/paper
chitalka stop                      # читалка текущего проекта
chitalka stop 12345                # PID из списка
chitalka stop --root ~/paper
chitalka stop --all                # все читалки текущего пользователя
chitalka stop --all --force        # SIGKILL оставшихся после SIGTERM и ожидания
```

Процессы проверяются через `ps`; новые запуски дополнительно регистрируются в
`~/.local/state/chitalka/sessions/` (либо `$XDG_STATE_HOME/chitalka/sessions/`).
Старые запуски тоже обнаруживаются. Перед сигналом сверяются владелец, время запуска
и команда; устаревшая запись PID не служит основанием для остановки другого процесса.
Вместе с reader завершаются его дочерние процессы, включая latexmk и TeX.
Если после аварии остался зарегистрированный latexmk, он показывается отдельной строкой.
PDF, исходники и комментарии сохраняются. Без доступа к `ps` остановка отказывается работать.

#### Tab-автодополнение

```sh
chitalka completion zsh --install
# или: chitalka completion bash --install
```

В новом терминале Tab дополняет команды, флаги, PDF/Markdown/ноутбуки/папки, движки сборки,
ID комментариев и PID запущенных сессий. Установка идемпотентна и сохраняет
остальной конфиг оболочки. В текущем zsh:

```sh
source ~/.local/share/chitalka/completion/chitalka.zsh
```

Команды и читалка пишут один файл под блокировкой, правки не теряются.

#### Возможности

- Замечание агенту к выделенному: `C`, или `1`–`5` сразу с категорией (опечатка, переписать,
  факт, вопрос, мысль); переписка с агентом в карточке.
- Личная заметка: `N` (с выделением или без); вкладка «Мои заметки», `J`/`K` по заметкам.
- Место в исходниках: по SyncTeX — точные `файл:строка–строка`, если PDF собран
  с `-synctex=1`; иначе поиск по словам.
- Открыть место в nvim: кнопка `файл:строка` на карточке или `E`. Новая вкладка kitty
  (`allow_remote_control yes`), иначе новое окно; своя команда — `--editor "… {file} {line}"`.
- `--watch`: latexmk в фоне, состояние сборки в шапке, клик по ошибке открывает её строку
  в nvim, новые сборки загружаются сами. Лог — в `~/.local/state/chitalka/latexmk/`,
  путь печатает `chitalka where`.
- Ссылки в PDF (литература, формулы, теоремы): клик — переход, `Alt+Left` — назад,
  наведение — предпросмотр места назначения.
- Выделение формул сплошными блоками, а не по символам.
- Масштаб: `Ctrl`/`Cmd` + `=`, `-`, `0` (по ширине).
- Панели: `[` оглавление, `]` комментарии, `H` шапка, `F` режим чтения.
- Дерево файлов: `Пробел` `e`, выход `:q`.
- Тема: `D` светлая или тёмная, `I` тёмные страницы. Шрифт интерфейса — `font_family`
  из `~/.config/kitty/kitty.conf` или `--font`.
- Поиск `/`, переход на страницу `G`, следующий и предыдущий комментарий `J`/`K`,
  все клавиши — `?`.

#### Тесты

```sh
uv run --no-project --with pytest python -m pytest -q
```

Проверка в настоящем браузере (необязательная зависимость только для разработки):

```sh
npm install --prefix /tmp/chitalka-browser-test --no-save playwright-core@1.64.1
PLAYWRIGHT_MODULE=/tmp/chitalka-browser-test/node_modules/playwright-core node tests/browser_markdown.cjs
```

Тест запускает отдельный сервер во временной папке и headless Chrome, проверяет
выделения, формулы, ноутбук (картинки, выводы, замечание к ячейке), дерево файлов, поиск, комментарии, ответы CLI, автообновление и защиту от
устаревшей привязки. На macOS находит установленный Google Chrome; иначе задайте
`CHROME=/путь/к/chrome` (или установите браузер Playwright). Снимки светлой и тёмной
тем сохраняются в системную временную папку.
